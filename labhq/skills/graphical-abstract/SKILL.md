# graphical-abstract

한 장에 메시지 하나만 남기는 과학 SVG를 만든다. 보고서의 주장과 숫자를 먼저 고정하고 그림은 그 내용을 압축한다.

## 구성

- 그래픽 초록은 `질문 → 자료 → 방법 → 핵심 결과 → 결론` 순서로 읽히게 한다.
- 분석 그림은 같은 흐름에서 필요한 칸만 남긴다. 짧은 한국어 라벨을 쓰고 기술 용어는 원문을 유지한다.
- 숫자, 표본 수, 효과 크기, 구간, 날짜는 보고서와 같은 값만 쓴다. 새로 계산하거나 반올림하지 않는다.
- 한 장에 결론을 하나만 둔다. 불확실성이나 조건이 결론을 바꾸면 같은 장에 짧게 적는다.

## 디자인 토큰

| 카드 | `#FFFFFF` |

글꼴은 `'Noto Sans KR', 'Apple SD Gothic Neo', 'Malgun Gothic', sans-serif`를 쓴다. 둥근 카드, 충분한 안쪽 여백, 왼쪽에서 오른쪽으로 이어지는 짧은 화살표를 기본 문법으로 삼는다. 강조색은 의미가 다른 묶음에만 쓴다.

## 산출 계약

- SVG 원본만 낸다. PNG와 화면 캡처는 산출물로 만들지 않는다.
- 모든 보이는 글자는 `<text>`로 둔다. 글자를 path로 바꾸지 않는다.
- 루트 `<svg>`에 `role="img"`와 `aria-labelledby`를, 첫 자식에 구체적인 `<title>`과 `<desc>`를 둔다.
- 외부 폰트, 이미지, JavaScript, `foreignObject`를 넣지 않는다.
- 시작점은 [templates/graphical-abstract.svg](templates/graphical-abstract.svg)다.

## 작업 순서

1. 보고서에서 질문, 자료, 방법, 핵심 결과, 결론과 그대로 옮길 숫자를 표로 뽑는다.
2. 같은 메시지를 담은 초안 두 방향을 만든다. 정보 순서와 카드 배치가 서로 달라야 한다.
3. 세 관점으로 비평한다: 과학적 정확성, 처음 보는 독자의 읽기 순서, 접근성·시각 균형.
4. 한 방향을 골라 SVG로 렌더한다. 잘림, 겹침, 작은 글자, 낮은 대비를 직접 확인한다. QA용 렌더는 임시로만 쓰고 PNG·캡처를 납품하지 않는다.
5. 문제를 고친 뒤 보고서의 숫자와 문장을 다시 대조한다.
