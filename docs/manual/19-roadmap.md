## 로드맵

v1.0 범위는 PI 지침([#1336](https://github.com/ehojune/bioinfo-team-3d/issues/1336), 2026-11-09)으로 정했습니다. 그 전의 세분화 로드맵(v0.25~v1.25, PI 결정 ⑥ #298, 2026-10-03)은 아래 지난 기록과 v1.0 이후 목표로 옮겼고, 원래 표는 `53a5b339` 판 이 파일에 있습니다.

| 버전 | 정의 | 통과 기준 | 지금 | 남은 것 |
|---|---|---|---|---|
| v1.0 | 생명정보 연구자가 날마다 믿고 쓰는 코어 연구팀. CSO → 문헌 조사 → 분석(bioinfo-agent) → 생물학 해석 → 다른 회사 모델의 교차 리뷰가 로컬·WSL·HPC에서 한 HPC 세션을 나눠 쓰며 공개 데이터 연구를 끝낸다 | 마감 과제 네 건 종료: HPC 접속 D단계(#1295), 세션 공유(#1332), 다중 직원 HPC 시운전(#1331), KRAS 문헌 연구 완주(#910) | #1295·#1332·#910 종료. #1331은 airway RNA-seq 시운전 중 | #1331 완주 |

**v1.0에서 기본으로 꺼 둔 v2.0 확장.** 코드는 남아 있고 설정으로 켭니다.
- 시맨틱·온톨로지 2·3층 검증: `semantics.mode`, `research.semantic_report` ([의미 모델](14-semantic-model.md))
- Paper2Agent 파견직 채용: `recruit.enabled` ([파견직 제도](10-contract-staff.md))

**지난 선언.**
- v0.25(2026-10-04): PI 공개 데이터 요청 세트 5건 중 4건이 개발자 손 없이 리뷰 accept까지 갔다
- v0.5(2026-10-08): 연구 요청 2건이 CP1 → CP2 → 리뷰 accept → claim 앵커 보고서까지 갔고 `labhq verify`가 exit 0이었다

**v1.0 이후 목표** (옛 로드맵에서 옮김):
- 통제 데이터 연구 1건. 원본이 클러스터 밖이나 LLM 대화로 나가지 않았음을 감사 기록으로 보인다(옛 v0.9). 지금 Windows 러너는 restricted 구역이 있으면 뜨지 않는다
- 다른 연구자가 문서만 보고 설치해 공개 데이터 요청 1건을 끝낸다(옛 v0.95). Windows 새 clone·venv 자동 리허설과 `labhq init`·doctor는 있다
- 다른 연구자가 자기 통제 데이터로 연구 문제 2건을 푼다(옛 v1)
- 논문 초안 1편. 그림·인용이 claim 앵커로 산출물에 이어진다(옛 v1.25)
- 실행 중 직원 제어와 폭주 차단기(#59). 직원 제어는 들어갔습니다([직원 제어](06-web-office.md#직원-제어)). 차단기는 그림자로만 동작합니다: runner가 같은 도구·입력 8번 연속이나 실패한 도구 호출 5번 연속을 보면 `agent.breaker` 이벤트와 피드 경고를 한 번 내고, 직원은 멈추지 않습니다
- 요청 간 기억·프로젝트 메모리(#60), 인사고과(평가 세트)와 정식 수습 평가(논문 예제 재현)

- **거버넌스(정부) 층**: 연구소들 위에서 규칙·감사·예산을 맡는 기관. 구성은 보류

- 클라우드 상주 에이전트(#79), 프로젝트 보고 채널 고르기(#70)
