## Checklists

For each item, the plan answers with one of `step:<step>` (done in that step), `assumption: <reason>` (not done, with the reason) or `not_applicable: <reason>` (does not apply). The source literature is in [topic checklist sources](reference/topic_checklists_sources.md) (Korean).

### bulk_rna_seq

| id | Check | Why |
|---|---|---|
| `batch` | Check the processing batch (scan date, array/lane, institution) for confounding with the comparison groups, and put it in the model or report it as a limit | So that technical differences are not read as biological differences |
| `pairing` | For samples from the same patient or donor, keep the pairing in both the main model and the gene-set test, and state the unpaired samples | So that individual differences are not wrongly counted as a condition effect |
| `gene_set_test` | Rank the gene-set test by the main model's statistic or run it in a pairing-preserving way, and do not use a pairing-ignoring retest as the main result | So that the main analysis's pairing and adjustment are preserved in the pathway test too |
| `independent_validation` | If an independent cohort or dataset exists, validate the key result, and if not, state why | To check whether the conclusion fits only one dataset |

### single_cell_rna_seq

| id | Check | Why |
|---|---|---|
| `pseudobulk` | Compare between donors at the donor level (pseudobulk and so on), not the cell level | To prevent the error of counting cells as independent biological replicates |
| `qc` | State the per-sample QC criteria and the handling of doublets and ambient RNA | Because per-sample quality and contamination can look like group differences |
| `batch` | Check the batch effect before and after integration | Because integration can erase biological signal or leave technical differences |

### bulk_deconvolution

| id | Check | Why |
|---|---|---|
| `reference_profile` | Record the source, tissue and cell-type scope, construction method and version of the reference cell profile | Because a reference that does not match the target tissue or lacks cell types distorts the estimated proportions |
| `mixture_validation` | Validate the error and correlation of the estimates on synthetic mixtures or data with known cell proportions | Because without data that have true proportions, the deconvolution accuracy on real samples is hard to judge |
| `rare_cell_limit` | Evaluate the minimum detectable proportion and false detection of rare cell types separately and state the interpretation limits | Because at low proportions the loss of power and confusion with other cell types' signals grow |
| `cohort_cross_validation` | Separate reference construction from performance evaluation by patient or cohort and run leave-out cross-validation | Because if the same patient or cohort is on both sides, generalization performance is inflated |
| `normalization_match` | Match and record the scale, normalization and gene-identifier handling of the bulk mixture and the reference profile | Because differences in input transformation and normalization can change the estimation error as much as the choice of method |

### spatial_transcriptomics

| id | Check | Why |
|---|---|---|
| `spot_qc` | State the per-spot or per-cell QC criteria (detected gene count, UMI count, exclusion of off-tissue spots) | Because off-tissue or damaged spots can look like spatial patterns |
| `deconvolution_reference` | For a spot-level technology, state the reference single-cell data and its source used for cell-type deconvolution | If the reference does not match the tissue, the cell composition estimate is off |
| `section_replicates` | Do spatial variation and region comparisons with a method that accounts for spatial autocorrelation, and state the section- or sample-level replicates | Counting spots as independent replicates inflates significance |

### atac_seq

| id | Check | Why |
|---|---|---|
| `library_qc` | Report TSS enrichment, FRiP, the fragment-length distribution (nucleosome periodicity) and the mitochondrial read fraction | If library quality is poor, differences in accessibility can be technical noise |
| `blacklist` | Exclude blacklist regions and state how duplicate reads were handled | To keep repeat sequences and artifact signals from being called as peaks |
| `differential_model` | For differential accessibility, state the consensus peak definition and judge with a count model that has biological replicates | Differences cannot be judged by peak overlap alone |

### chip_seq

| id | Check | Why |
|---|---|---|
| `input_control` | Use an input (or IgG) control and state the peak-calling method and threshold | Background signal must be subtracted to tell binding sites apart |
| `replicate_reproducibility` | Decide the final peaks by reproducibility between replicates (IDR and so on) | A peak present in only one replicate is likely noise |
| `library_qc` | Report FRiP, library complexity (NRF, PBC) and cross-correlation metrics (NSC, RSC), and exclude the blacklist | Antibody and library quality are the premise for interpreting results |

### cut_and_run

| id | Check | Why |
|---|---|---|
| `controls_normalization` | State the controls such as IgG and whether spike-in normalization was used | To separate background from changes in total signal |
| `peak_calling` | State the peak-calling method suited to low-background data (SEACR and so on) and its threshold | Default settings for ChIP can add false peaks or miss true ones in this kind of data |
| `replicates` | Use biological replicates per condition and report the agreement between replicates | A single-sample result cannot be generalized |

### dna_methylation

| id | Check | Why |
|---|---|---|
| `conversion_rate` | Report the bisulfite conversion efficiency (non-CpG methylation rate or spike-in) | Incomplete conversion overestimates methylation |
| `coverage_snp` | State the minimum per-CpG coverage criterion and the exclusion of C>T SNP positions | Low coverage and SNPs distort methylation levels |
| `differential_model` | For differential methylation, judge with a model that reflects replicates and coverage (beta-binomial and so on) | Comparing only proportions ignores coverage differences |

### germline_wgs_wes

| id | Check | Why |
|---|---|---|
| `pipeline_reference` | State the alignment, duplicate-marking and variant-calling process (for example GATK best practices) and the reference genome version | The pipeline and reference version change the variant list |
| `sample_qc` | Report sample QC (mean coverage, sex concordance, relatedness and contamination checks) | To catch sample swaps and contamination before analysis |
| `variant_filtering` | Report the variant filtering criteria (VQSR or hard filters) and call-set metrics such as Ti/Tv | Because filtering sets precision and sensitivity together |

### somatic_wgs_wes

| id | Check | Why |
|---|---|---|
| `matched_normal` | Filter germline variants with a matched normal sample, and without one (tumor-only) with population germline data such as gnomAD, then state the remaining misclassification risk as a limit | A panel of normals filters only technical artifacts and can wrongly call that patient's own germline variants as somatic |
| `purity_contamination` | Estimate and report tumor purity and cross-contamination | Purity and contamination change VAF interpretation and power |
| `artifact_filters` | State the panel of normals, filters for artifact variants such as FFPE and oxidation, and the VAF and depth criteria | Sample processing and sequencing artifacts look like somatic variants |

### rare_disease_genomics

| id | Check | Why |
|---|---|---|
| `phenotype_hpo` | Organize the phenotype as HPO terms and use it for candidate prioritization | The phenotype is the main basis for narrowing the many candidates |
| `inheritance` | Consider the pedigree and inheritance mode (de novo, recessive, X-linked), and use family data such as a trio when available | To filter out candidates that do not fit the inheritance mode |
| `acmg_classification` | Classify variant interpretation by ACMG/AMP criteria with evidence, and state that clinical confirmation needs a confirmatory test | So that a research analysis result is not read as a diagnosis |

### ont_long_read

| id | Check | Why |
|---|---|---|
| `basecalling` | Report the basecaller and model versions and the read quality and length distribution (N50) | Accuracy differs greatly by basecaller version |
| `error_profile` | Use tools and polishing suited to error characteristics such as homopolymers, and be careful interpreting short indels | ONT-specific errors can look like indel variants |

### pacbio_long_read

| id | Check | Why |
|---|---|---|
| `read_type` | Distinguish HiFi from CLR and report read accuracy and length distributions | The suitable tools and expected accuracy differ by read type |
| `platform_tools` | Use tools and models tailored to PacBio data for alignment and variant calling, and state the versions | Defaults for short reads do not match the error characteristics of long reads |

### long_read_transcriptomics

| id | Check | Why |
|---|---|---|
| `isoform_definition` | State the selection of full-length reads and the criteria for accepting an isoform (supporting read count, 5' and 3' completeness) | Truncated reads can look like new isoforms |
| `novel_isoform_support` | Confirm a novel isoform with reference annotation, short reads or independent evidence, or mark it as a candidate | A novel isoform with a single piece of evidence may be an artifact |
| `quantification` | State the isoform quantification method and the replicates per condition | Isoform differences cannot be judged without replicates |

### metagenome_assembly

| id | Check | Why |
|---|---|---|
| `bin_quality` | Report the MAG completeness and contamination (CheckM and so on) and the quality grade (MIMAG) | A contaminated bin creates a genome that does not exist |
| `host_removal` | State the host read removal and the assembly approach (per sample or co-assembly) and parameters | Host sequences and the assembly choice change the genomes recovered |

### metagenomic_taxonomy

| id | Check | Why |
|---|---|---|
| `database_version` | State the classification database and its version | Taxonomic results depend heavily on the database |
| `negative_controls` | Check contamination with negative controls such as extraction and reagent blanks | In low-biomass samples, reagent contamination can dominate the result |
| `compositional_analysis` | Compare relative abundance with methods suited to compositional data (CLR transform and so on) and handle differences in sequencing depth | Comparing proportional data as is creates spurious correlations |

### amplicon_sequencing

| id | Check | Why |
|---|---|---|
| `region_primers` | State the target region (for example 16S V4) and how primers were removed | The region and primers determine which taxa can be detected |
| `denoising` | State the ASV denoising (DADA2 and so on) and chimera removal criteria | Sequencing errors and chimeras create false taxa |
| `controls` | Check contamination and accuracy with negative controls and a mock community | Without controls, contamination cannot be told from real signal |

### viral_genomics

| id | Check | Why |
|---|---|---|
| `consensus_masking` | For the consensus, mask with N the positions below the minimum depth criterion and state that criterion | Bases at low-coverage positions cannot be trusted |
| `primer_dropout` | For amplicon designs, remove primers and check for amplicon dropout regions | Primer sequences and dropout regions look like variants or deletions |
| `lineage_versions` | State the lineage and clade assignment tools and data versions (Pangolin, Nextclade and so on) | When the version changes, the lineage of the same sequence changes |

### bacterial_genome_assembly

| id | Check | Why |
|---|---|---|
| `completeness_contamination` | Report completeness and contamination (CheckM, BUSCO) and coverage | An incomplete or contaminated assembly makes judgments about gene presence wrong |
| `species_identity` | Confirm the identity of the sample by species identification (ANI and so on) | So that a mislabeled strain is not interpreted as another species |
| `annotation_versions` | State the annotation tools and database versions (Bakta, Prokka, antibiotic-resistance DBs and so on) | Gene and resistance calls differ by annotation version |

### alternative_splicing

| id | Check | Why |
|---|---|---|
| `replicates_junctions` | State the biological replicates per condition and the minimum junction-read criterion | Splicing differences cannot be judged without replicates and junction evidence |
| `depth_read_length` | Report whether the read length and depth are sufficient for splicing quantification | Short reads and low depth make event estimates unstable |
| `event_support` | Confirm major events with sashimi plots or independent evidence, or mark them as candidates | Event calls from a single tool include artifacts |

### microarray_expression

| id | Check | Why |
|---|---|---|
| `batch` | Check the processing batch (scan date, array/lane, institution) for confounding with the comparison groups, and put it in the model or report it as a limit | So that technical differences are not read as biological differences |
| `pairing` | For samples from the same patient or donor, keep the pairing in both the main model and the gene-set test, and state the unpaired samples | So that individual differences are not wrongly counted as a condition effect |
| `gene_set_test` | Rank the gene-set test by the main model's statistic or run it in a pairing-preserving way, and do not use a pairing-ignoring retest as the main result | So that the main analysis's pairing and adjustment are preserved in the pathway test too |
| `independent_validation` | If an independent cohort or dataset exists, validate the key result, and if not, state why | To check whether the conclusion fits only one dataset |
| `probe_mapping` | State the probe-to-gene aggregation rule and the platform annotation version | Because multiple probes and outdated annotation can change per-gene results |

### proteomics

| id | Check | Why |
|---|---|---|
| `fdr_control` | Set the FDR at PSM, peptide and protein levels by target-decoy (usually 1%) and state the protein inference rules | Because identification errors accumulate toward the protein level |
| `missing_values` | State the imputation method and normalization that fit the nature of missing values (below the detection limit or random) | Missing values of low-abundance proteins are not random, so the imputation method changes differential results |
| `batch` | Check the processing batch such as MS run order and TMT plex for confounding with the comparison groups, and put it in the model or report it as a limit | So that instrument drift and plex differences are not read as biological differences |

### proteomics_dia

| id | Check | Why |
|---|---|---|
| `spectral_library` | State the spectral library approach (experimental library, predicted, library-free) and the analysis software and version | The library source changes the identification count and FDR estimate |
| `fdr_control` | Report precursor and protein FDR separately per run and across the whole experiment | With many runs, a per-run 1% FDR is inflated across the experiment |
| `missing_values` | State the imputation method and normalization that fit the nature of missing values (below the detection limit or random) | Missing values of low-abundance proteins are not random, so the imputation method changes differential results |

### single_cell_proteomics

| id | Check | Why |
|---|---|---|
| `carrier_blank` | State the carrier channel ratio and the blank well control, and report cell signal relative to blank | An excessive carrier distorts single-cell quantification, and without a blank the background signal cannot be separated |
| `cell_qc` | State the per-cell QC criteria (identified peptide and protein counts, CV of repeated peptides) and the number of cells excluded | Because low-quality cells can look like clusters or group differences |
| `batch` | Check the analysis batch (LC-MS run, TMT plex, plate) for confounding with cell type and condition, and put it in the model | Single-cell data have many missing values, so batch effects easily look like biological clusters |

### spatial_proteomics

| id | Check | Why |
|---|---|---|
| `antibody_validation` | State the validation of the antibody panel (control tissue, comparison with single staining) and the clones | Unvalidated antibody signals do not guarantee the real protein distribution |
| `segmentation_qc` | State the cell segmentation method and how segmentation quality was checked | Segmentation errors mix neighboring cells' signals and create false co-expression |
| `spillover` | State whether and how channel-to-channel spillover was corrected (a spillover matrix and so on) | Because signal bleed between channels looks like co-expressing cell types |

### metaproteomics

| id | Check | Why |
|---|---|---|
| `search_database` | State the composition (for example from a paired metagenome) and size of the search protein DB, whether host proteins are included, and the FDR criterion | If the DB does not match the sample or is too large, the identification count and FDR estimate collapse |
| `peptide_attribution` | State the rule for peptides shared by several taxa in taxon and function assignment (LCA and so on) and the tool and DB versions | Assigning shared peptides to a single taxon distorts the composition |

### metabolomics

| id | Check | Why |
|---|---|---|
| `qc_samples` | Put pooled QC and blanks throughout the run, filter features by the RSD criterion of the QC, and correct signal drift | Because instrument signal drift and contaminant features can look like group differences |
| `batch` | Randomize the injection order and check the analysis batch for confounding with the comparison groups | If injection order and batch overlap with the groups, technical and biological differences cannot be separated |
| `annotation_confidence` | Report metabolite identification together with its confidence level (MSI level 1–4 and so on) and basis (standard, MS/MS match) | So that a putative annotation matched only by mass is not read as a confirmed identification |

### spatial_metabolomics

| id | Check | Why |
|---|---|---|
| `annotation_confidence` | Annotate metabolites by mass accuracy and with FDR-controlled annotation (METASPACE and so on) and state the FDR level | High-resolution mass alone cannot filter out isomers and chance matches |
| `background_normalization` | Identify signal from the matrix and off-tissue regions as background, subtract it, and state the normalization method (TIC and so on) | Because matrix peaks and ionization differences look like spatial patterns |

### gwas

| id | Check | Why |
|---|---|---|
| `sample_variant_qc` | State the sample QC (missingness, sex mismatch, relatedness, heterozygosity), the variant QC (call rate, MAF, HWE) and the imputation quality criteria | Genotyping errors and sample swaps create false associations |
| `population_structure` | Adjust for population structure and relatedness with principal components or mixed models, and report genomic inflation (λGC or LDSC intercept) | If population stratification overlaps the phenotype, false associations arise |
| `significance_replication` | Use the genome-wide significance level (5×10⁻⁸) and state whether it replicated in an independent sample | A single-study signal from millions of tests is a candidate until replicated |

### structural_variant_calling

| id | Check | Why |
|---|---|---|
| `merge_criteria` | When merging caller outputs or SVs across samples, state the merge criteria (breakpoint distance, size agreement) and the tool | The SV count and sharing across samples change with the merge criteria |
| `validation` | Confirm major SVs with independent evidence such as read visualization, long reads or PCR, or mark them as candidates | SV calls in repeat regions have many false positives |

### de_novo_genome_assembly

| id | Check | Why |
|---|---|---|
| `contiguity_completeness` | Report contig and scaffold N50, total size, BUSCO completeness and the lineage version | Contiguity and completeness set the questions an assembly can answer |
| `base_accuracy` | Report base accuracy by a k-mer-based QV (Merqury and so on), and if phasing was done, state its accuracy too | Even with good contiguity, many base errors throw off gene models and variants |
| `contamination` | State the contamination screening (FCS-GX, BlobToolKit and so on) and how organelle sequences were separated | Contaminant contigs can be interpreted as that organism's genes |

### genome_annotation

| id | Check | Why |
|---|---|---|
| `repeat_masking` | Before gene prediction, soft-mask with a species-tailored repeat library and state the method | Repeats and transposons create false gene models |
| `evidence_support` | Support the gene models with RNA-seq and protein evidence and state the evidence and tools used (BRAKER, MAKER and so on) | Ab initio prediction alone has many gene-structure errors |
| `annotation_completeness` | Report the BUSCO completeness of the annotated protein set and evidence-agreement metrics (AED and so on) | So that genes the annotation missed are not interpreted as genes that do not exist |

### pangenomics

| id | Check | Why |
|---|---|---|
| `graph_construction` | State the pangenome construction method (Minigraph-Cactus, PGGB and so on), the haplotypes included and the reference coordinate system | The graph and variant representation change with the construction method and reference coordinates |
| `input_assembly_quality` | Report the quality (QV, completeness) and phasing status of the assemblies included | Assembly errors remain in the graph as false variants |
| `gene_family_thresholds` | For a gene-level pangenome, state the core and accessory definition thresholds, the clustering criteria and whether annotation errors were corrected | Thresholds and annotation errors greatly change the accessory gene count |

### phylogenetics

| id | Check | Why |
|---|---|---|
| `alignment_trimming` | State the multiple-alignment tool and the alignment trimming (trimAl and so on) criteria | Alignment errors and poorly aligned regions change the tree topology |
| `model_selection` | Choose the substitution model by model selection (ModelFinder and so on) and state it | A wrong model mis-estimates branch lengths and topology |
| `branch_support` | Report branch support (bootstrap, UFBoot, SH-aLRT) and do not use low-support branches in conclusions | A low-support split is not backed by the data |
| `recombination` | For bacterial or viral lineages, detect and remove recombinant regions (Gubbins and so on) or state it as a limit | Recombinant regions do not follow a single tree and distort topology and branch lengths |

### hi_c

| id | Check | Why |
|---|---|---|
| `library_qc` | Report the valid pair fraction, the cis/trans ratio, the long-range cis fraction and the duplication rate | If library quality is poor, the contact matrix is filled with noise |
| `normalization_resolution` | State the matrix normalization (ICE, KR and so on) and the analysis resolution, and report whether that resolution is supported by depth | If the resolution is high relative to depth, loop and TAD calls are unstable |
| `replicate_reproducibility` | Report reproducibility between replicates (HiCRep and so on) and do condition comparisons with a method that has replicates | Contact differences cannot be judged without replicates |

### spatial_epigenomics

| id | Check | Why |
|---|---|---|
| `library_qc` | Report the fragment count per spot, TSS enrichment and FRiP, and exclude off-tissue spots | Few fragments per spot make quality differences easily look like spatial patterns |
| `section_replicates` | Do spatial variation and region comparisons with a method that accounts for spatial autocorrelation, and state the section- or sample-level replicates | Counting spots as independent replicates inflates significance |

### multi_omics_integration

| id | Check | Why |
|---|---|---|
| `sample_matching` | Confirm the sample pairing across omics (same individual and time point) and state how samples present in only one omics were handled | Silently dropping mismatched or missing samples distorts the integration result |
| `per_omics_preprocessing` | Normalize and batch-correct each omics separately before integration, and report each omics' contribution per factor and cluster | One large-scale omics can dominate the integration result |
| `cross_validation` | For supervised integration models (DIABLO and so on), report performance by cross-validation and do feature selection inside the validation folds | Selecting and evaluating on the same data inflates performance |

### single_cell_multiome

| id | Check | Why |
|---|---|---|
| `modality_qc` | Apply modality-specific QC to each cell together (RNA UMI and mitochondrial fraction, ATAC TSS enrichment and fragment count, protein background correction) and state the criteria | Low-quality cells that pass only one modality blur the integrated clusters |
| `pseudobulk` | Compare between donors at the donor level (pseudobulk and so on), not the cell level | To prevent the error of counting cells as independent biological replicates |
| `peak_gene_links` | Derive peak-gene links by correlation corrected for GC and accessibility background, and do not assert regulatory relationships without independent evidence | Correlation within the same cells does not show causal regulation |

### spatial_multiomics

| id | Check | Why |
|---|---|---|
| `registration` | State the registration method between sections and modalities and the registration error | If registration is off, signals from different positions get paired and interpreted |
| `section_replicates` | Do spatial variation and region comparisons with a method that accounts for spatial autocorrelation, and state the section- or sample-level replicates | Counting spots as independent replicates inflates significance |

### perturb_seq

| id | Check | Why |
|---|---|---|
| `guide_assignment` | State the criteria for assigning guides to cells (UMI threshold), the handling of cells with no guide or several, and the MOI | If wrongly assigned cells mix in, perturbation effects are diluted or scrambled |
| `perturbation_efficiency` | Check the knockdown or knockout efficiency of the target genes and handle cells that escaped perturbation (Mixscape and so on) | If unperturbed cells mix in, the effect is underestimated |
| `nontargeting_controls` | Judge effects by comparing with non-targeting guide cells of the same batch | So that culture and batch differences are not mistaken for perturbation effects |

### immune_repertoire_sequencing

| id | Check | Why |
|---|---|---|
| `umi_error_correction` | Correct PCR and sequencing errors and amplification bias with UMIs and state the consensus criteria | Amplification errors create false clonotypes and inflated diversity |
| `germline_annotation` | State the V(D)J assignment tool and the germline reference version (IMGT and so on) and keep results in the AIRR standard format | Gene assignment and somatic mutation calls differ by reference version |
| `diversity_depth` | For diversity and clonality comparisons, equalize reads or cells per sample (rarefaction and so on) or state the effect of sample size | Diversity metrics depend heavily on sample size |

### metagenomic_functional_profiling

| id | Check | Why |
|---|---|---|
| `database_version` | State the functional annotation database (UniRef, KEGG, eggNOG and so on), its version and the tool | The database version changes the functions and pathways assigned |
| `unmapped_fraction` | Report, per sample, the fraction of reads with an assigned function and the unassigned fraction | Differences in assignment rate can look like differences in functional abundance |
| `compositional_analysis` | Compare relative abundance with methods suited to compositional data (CLR transform and so on) and handle differences in sequencing depth | Comparing proportional data as is creates spurious correlations |

### metagenome_binning

| id | Check | Why |
|---|---|---|
| `bin_quality` | Report the MAG completeness and contamination (CheckM and so on) and the quality grade (MIMAG) | A contaminated bin creates a genome that does not exist |
| `binning_refinement` | State the binning tool, whether coverage from several samples was used, and the bin refinement method (DAS Tool and so on) | The number of recovered genomes and the contamination differ greatly by binning approach |
| `dereplication` | State the criteria for removing duplicate MAGs across samples (ANI 95% and so on) and the classification tool and DB version (GTDB-Tk and so on) | So that the same genome is not counted several times and different taxonomic names are not used per version |

### metatranscriptomics

| id | Check | Why |
|---|---|---|
| `rrna_host_removal` | Report the fraction of reads left after rRNA removal (experimental or in silico) and host read removal | If rRNA and host reads remain, microbial transcription signal is buried |
| `dna_normalization` | Correct transcription differences by the DNA abundance of the paired metagenome to separate expression changes from taxon abundance changes | So that a taxon increase is not mistaken for an expression increase |

### variant_effect

| id | Check | Why |
|---|---|---|
| `population_frequency` | Report the dataset version of a population resource such as gnomAD and the allele frequency overall and in major ancestry groups, and if the variant was not observed, state that the lookup succeeded but it was absent | Common variants are unlikely to cause rare disease, and frequencies differ by population |
| `clinical_assertions` | Report the ClinVar classification with its review status and evaluation date, and confirm it is the same entry as the input allele | Because the same variant is interpreted differently by different submitters, and a registered entry can be a different allele |
| `consequence_annotation` | Report the variant consequence type with VEP, based on the MANE Select (or canonical, if none) transcript, and state the Ensembl release and reference genome version | Because the consequence of the same variant differs by transcript, and annotation changes when the version changes |
| `missense_prediction` | For coding missense variants, report the AlphaMissense score and class on the same transcript basis, and write not applicable for other variants | Because for a missense variant not in ClinVar, a prediction combining structure and evolutionary information is a supporting clue |
| `regulatory_splicing` | For non-coding, regulatory and splicing variants, report the ref/alt score, quantile, tissue and direction of the recommended scorer of alphagenome_variant in labhq_annot (when an AlphaGenome key and SDK exist); if the tool is absent, substitute a prediction such as SpliceAI or public regulatory annotation and state what was used | Because variants that do not change the protein are not handled by AlphaMissense |
| `concordance_limits` | Compare whether frequency, ClinVar, VEP and predictions agree, mark the variants that disagree separately, and write in the limits that predictions are not clinical evidence. An ACMG/AMP classification is made only when requested | So that a prediction is not read as a diagnosis and only one side of conflicting evidence is not picked |
