# HPC D단계(#1295): 실제 사이트에 한 번 접속해 읽기 전용으로 확인

사이트의 호스트·사용자·경로·제품 이름은 적지 않습니다. 원문 로그는 작업자의 로컬 폴더에만 있습니다.

| 시도 | 일시 | 결과 |
|---|---|---|
| 1차 | 2026-11-07 | 접속이 셸 단계 전에 끊겨 명령을 하나도 실행하지 못했습니다(첫 시도와 재접속 1회, 로그인 2회). |

## 1차에서 알게 된 것
- PI 승인 범위: 읽기 전용(신원·큐 조회·작업 폴더 `pwd -P`·`ls`), 잡 제출·파일 올리기·원격 쓰기 없음, 로그인 상한 요청당 10·하루 30.
- 접속 명령은 PI의 게이트웨이 skill과 같은 방식(`ssh -tt`, 호스트 키 고정)이고, 터널이 LISTENING인 것은 접속 직전에 확인했습니다.
- 세션 관리자가 연결 직후 준비 명령을 바로 보냈는데, 게이트웨이가 로그인 처리 중에 들어온 입력에 접속을 끊는 것으로 보입니다. 기존 skill 스크립트는 셸 프롬프트가 나온 뒤에 보냅니다.
- 실패한 접속의 출력은 오류에 싣지 않는 설계라 원문을 확인하지 못했습니다.

## 고친 것(PR의 `--1295-wait-banner`)
- 첫 출력(배너·프롬프트)이 나오고 조용해질 때까지(프로필 `first_output_wait_s`) 기다린 뒤 첫 명령을 보냅니다.
- 접속 실패 시 받은 원문은 로컬 진단 폴더(`LABHQ_HPC_DIAG_DIR`)에만 남깁니다. 오류 문장과 피드에는 싣지 않습니다.
- `remote_exec: false`와 scheduler를 모순으로 보던 프로필 검사를, 접속 명령이 있을 때는 모순으로 보지 않게 고쳤습니다.
- 가짜 게이트웨이에 "너무 이른 입력이 오면 끊는" 모드를 더해 대기가 없으면 끊기고 대기하면 통과하는 한 쌍을 시험합니다.

## 2차
병합 뒤 같은 승인 범위에서 한 번만 다시 시도합니다(재접속 최대 1회). 결과는 이 문서에 추가합니다.
