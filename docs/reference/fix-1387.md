## 2번 읽기 조사

- `ResearchResult`(`labhq/research/contract.py`)의 evidence `source.locator`는 `labhq/evidence/claims.py`가 정의한다. `cso.py`의 결과 계약 검증은 정정된 structured ledger를 원래 result에 저장하며 수집된 산출 파일 수정은 거부한다.
- `cso.py::_research_report`와 `portfolio.py::_source_evidence_rows`는 단계별 ledger를 `report_check.py::claim_evidence_rows`에 넘긴다. 후자는 출처 위치를 표시하고, portfolio는 이를 `docs/reference/claim_evidence.md`에 쓴다.
- `portfolio.py::build_portfolio_files`는 수집된 TSV/CSV 산출을 공개 가능 여부와 형식 보정 후 `tables/`에 옮긴다. `clinical_evidence.tsv`의 특정 writer는 일반 코드에서 찾지 못했다. 해당 단계가 작성한 산출인지 실제 실행 기록 확인이 필요하다.
- 제안 계약: producer step·claim/evidence ID, artifact ID와 해시·표의 행 키·열, 이전 값·새 값·근거를 구조화한다. 대상 중복·불일치·근거 누락은 거부하고 원본과 변경 이력을 보존한다. ledger와 파생 표를 같은 검증된 정정에서 만들고 둘을 함께 검증한다. QC 자유문장은 자동 적용하지 않는다.
- 합성 Table 1→Table 2는 ledger 미반영만 재현했다. 실제 KRAS 정정·원천표 writer와 전체 반영은 미검증이다. 후속 범위 후보는 `labhq/research/contract.py`, `labhq/evidence/claims.py`, `labhq/orchestrator/cso.py`, `labhq/evidence/report_check.py`, `labhq/portfolio.py`, 이 경로의 관련 시험이다. 실제 writer와 변경 경계 확인 후 확정한다.

## 해시 시간 제한

- 원격 scan과 입력 재검증은 일반 명령의 60초 대신 최대 1시간을 쓴다. 업로드 전체는 65분이며 shell 대기와 재연결도 이 시간에 포함한다. 제출 broker와 CLI 대기도 이 제한을 반영한다.
- 시간 초과나 불완전 scan은 성공한 목록으로 채택하지 않는다. 재시도는 파일 전체를 다시 해시한다. 실제 대용량 성능과 HPC 연결은 미검증이며 1시간을 넘는 scan은 완료되지 않는다.
