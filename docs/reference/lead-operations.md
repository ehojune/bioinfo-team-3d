## 2026-10-23 기준 기록

아래는 당시 정책의 보존본입니다. 현재 배정·리뷰·보고·한도를 승인하는 근거로 쓰지 않습니다.

| 시점 | 다음 행동 |
|---|---|
| 정기 점검 | 매시 :00·:20·:40에 worker·PR·문제·예산·다음 일을 확인하고 후속 조치(2026-10-20 갱신, 이전 10분) |
| 작업 완료 | 같은 담당자·세션이 다음 일을 이어받음 |
| P1 발견 | 같은 담당자가 수정 → 새 head 리뷰 → P1=0까지 반복. CI 통과도 병합 조건 |
| 리뷰·CI 대기 | driver가 기다리며 총괄이 반응을 확인. 무응답은 1회 재요청 뒤 정확한 head 직접 검토로 대체. 실제 P1·CI 조건은 유지 |
| 남은 P2 | 실사용 재현 가능성·결과 정확성·보안·반복 중단 영향과 수정 비용 대비 이득으로 총괄이 선별한 것만 issue. 경미·추정·중복은 원 PR 댓글 |
| 한도 도달 | 새 투입만 중단. 진행 중 작업·리뷰·CI·배포는 대기 |
| 후속 배정 | PI가 일반 개발을 재개함(2026-10-20). 열린 PR·실제 실패를 우선하고 완료 담당자에게 관련 작업을 예산·소유·공유 파일 순서에 맞춰 배정 |
| 중요한 분기 | 선택지·영향·권고를 분석해 PI에게 질문. 일반 구현은 총괄 판단 |
