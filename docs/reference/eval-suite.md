# 평가 묶음 설계 (#1383)

#1381 3절 평가 묶음의 설계입니다. 이 문서와 fixture로는 아무것도 실행하지 않습니다(모델 호출 · HPC · PI 인스턴스 0). 실행은 PI가 아래 "PI가 정할 것"을 채운 뒤 별도 issue로 합니다.

| 시험 | 재는 것 | 오프라인 산출 |
|---|---|---|
| 1 인용 감사 | 인용이 실재하고 인용문 · 수치가 원문에 있는가 | `scripts/citation_audit.py`, `tests/fixtures/eval_suite/citation_audit/` |
| 2 리뷰 보정 | 리뷰가 결론을 바꾸는 오류를 잡고 깨끗한 것을 건드리지 않는가 | `tests/fixtures/eval_suite/review_calibration/{clean,seeded,seeded_contrast}` |
| 3 짝 비교 | 같은 조건에서 labhq가 단독 에이전트보다 나은가 | 없음(질문 후보만) |
| 4 반증 반영 | 반증을 받았을 때 결정을 맞게 바꾸는가 | `tests/fixtures/eval_suite/falsification/cases.json`(정답 칸 비움) |

## 1. 인용 감사

**대조 항목과 등급**

| 항목 | major | minor |
|---|---|---|
| 식별자 | DOI · PMID 둘 다 없음, 조회 결과 없음, DOI와 PMID가 다른 저작물 | 조회 기록이 없어 확인 못 함 |
| 제목 | 등록 제목과 다른 저작물(토큰 겹침 < 0.8) | 대소문자 · 문장부호 · 서식 태그(`<i>`, `<sup>`, `&lt;sup&gt;`) 차이를 넘는 작은 차이(겹침 ≥ 0.8) |
| 인용문 | 원문에 없음 | 원문 텍스트가 묶음에 없거나, 원문 자리에 다른 파일을 가리키는 포인터만 있어(첫 줄 `# 포인터:` 또는 `# Pointer:`) 확인 못 함 |
| 수치 | 원문에 그 값이 적힌 자릿수로 없음(부호 포함) | 같음 |

- 인용 하나의 등급은 가장 나쁜 항목입니다. major가 하나라도 있으면 종료 코드 1입니다.
- 인용문 · 수치 대조는 `labhq/evidence/literal_check.py`를 그대로 씁니다(정규화, 쓰인 자릿수 비교).
- **입력:** `{"citations": [{id, doi, pmid, title, source, quotes, numbers}]}`. `source`는 묶음 안의 원문 텍스트 경로이고 묶음 밖은 읽지 않습니다. 수치는 문자열로 적습니다(JSON 숫자는 `2.970`이 `2.97`로 읽혀 자릿수를 잃음). 형식이 틀린 항목은 major이고 CLI에서는 입력 오류(exit 2)입니다. 원문의 `1e-5` · `1.2 × 10^-5`는 한 값으로만 읽고 유효숫자로 대조합니다.
- **조회 기록:** 스크립트는 조회를 보내지 않습니다. `--records`에 `"doi:<값>"`·`"pmid:<값>"` → `{found, title}`을 받습니다. 실제 기록은 실행 issue에서 인용당 DOI · PMID 각 1회 조회로 만들고 날짜와 함께 고정합니다.
- **한계:** 수치의 존재만 보고 문장의 방향("증가" · "감소")은 보지 않습니다. 방향 대조는 #1374의 보고서 검사 몫입니다.

## 2. 리뷰 보정

**오류 10종**(각 seeded 묶음의 `ERRORS.json`이 정답 키). 대조 뒤집힘(E07)은 모든 부호를 뒤집어 방향 오류(E01)를 상쇄하므로 `seeded_contrast` 묶음에 따로 둡니다. 나머지 9종은 `seeded`에 있습니다. 묶음마다 조회 기록(`records.json`)을 함께 넣어 인용 오류를 묶음만으로 찾을 수 있게 했습니다.

| 종류 | 정의 | 이 묶음에서 결론을 바꾸나 |
|---|---|---|
| direction | 본문의 증감과 표의 부호가 반대 | 예(E01) |
| table_text_mismatch | 본문 수치가 표와 다름 | 아니오(E02) |
| denominator | 비율 · 개수의 분모나 분자가 표와 다름 | 아니오(E03) |
| citation | 인용 식별자가 다른 저작물을 가리킴 | 아니오(E04) |
| shared_source | "독립" 근거가 같은 데이터셋 | 아니오(E05) |
| missing_run | 보고한 분석의 실행 기록 · 산출이 없음 | 예(E06) |
| contrast_reversed | 실행한 대조 방향이 본문 해석과 반대 | 예(E07) |
| multiple_testing | 보정하지 않은 p로 유의를 판정 | 아니오(E08) |
| covariate_dropped | 본문 설계식의 공변량이 실제 모델에 없음 | 예(E09) |
| outlier_unreported | 이상치 시료를 본문이 언급하지 않음 | 아니오(E10) |

- **결론을 바꾸는 오류:** 고치면 보고서 "결론" 절의 주장 가운데 하나의 상태가 바뀌는 오류입니다(뒷받침됨 ↔ 뒷받침 안 됨, 또는 효과 방향이 뒤집힘). 결론에 쓰이지 않는 부차 수치의 오류는 아닙니다.
- **검출:** 리뷰 지적이 정답 키의 같은 파일을 가리키고 같은 종류의 문제를 말하면 검출입니다. 심각도 표기는 따지지 않습니다.
- **셈법**
  - 결론 검출률 = 검출한 결론 변경 오류 / 4
  - 전체 검출률 = 검출한 오류 / 10
  - 오경보 = clean 묶음에 낸 "고쳐야 함"(P1 등급) 지적 수 + 두 seeded 묶음에서 정답 키에 없는 P1 지적 수
- **갈래:** 지금 리뷰 / 블라인드 초안(리뷰어가 결론을 모르고 먼저 쓴 뒤 대조) / 산출 대조 1회. 갈래마다 묶음 셋(clean · seeded · seeded_contrast)을 따로 줍니다(9회).
- **판정:** 결론 검출률이 오르고 오경보가 늘지 않은 갈래만 채택합니다. 같으면 비용이 낮은 쪽을 고릅니다. 지금 리뷰가 결론 변경 오류를 놓칠 때만 REVIEW v2 연결을 검토합니다(#1381 2절).

## 4. 반증 반영

- 사례 6건(계속 2 · 재설계 2 · 기권 2)의 틀은 `cases.json`에 있습니다. 질문 · 처음 가설 · 고정한 다음 행동 · 반증이 오는 단계 · 반증 내용을 적었고 **정답(`answer`)과 근거는 비워 뒀습니다.** PI가 실행 전에 채웁니다.
- 갈래: 단독 에이전트 / 지금 labhq / labhq + 재고 1회(`alternatives` · `change_signals` 칸 사용).
- **회복으로 세는 것:** 전제 · 비교 대상 · 데이터 · 실험 · 결정 가운데 정답에 맞게 바뀐 것이 하나 이상이고, 최종 행동이 정답(계속 · 재설계 · 기권)과 같을 때.
- **회복이 아닌 것:** 문구만 누그러뜨림("may", "suggests")과 결정이 그대로인 것.
- 같은 예산에서 재고 갈래의 회복이 지금 labhq보다 늘지 않으면 재고 단계를 버립니다.

## 6. 실행 순서와 중단

- 순서: 인용 감사 → 리뷰 보정 → 짝 비교 → 반증 반영.
- 기본 경로가 과학이 아닌 배관 문제(전송 · 계획 검증 · 산출 대조 거절 등)로 같은 질문에서 두 번 연속 멈추면, 짝 비교와 반증 반영을 멈추고 결함 issue를 엽니다. 그동안 두 시험은 판단이 아니라 고장을 잽니다.
- 상한을 넘은 실행은 그 자리에서 멈추고 실패 시도로 기록합니다.
