# labhq 2D 사무실 디자인 비평 (Claude, 독립 검토)

대상은 `http://localhost:8802/index.html?demo=1`이다. 데스크톱 1440×900과 폰 375×812에서 시작 화면, 진행 중 요청, 결정 카드, 작업판, 메신저, HPC, 직원 시트, 입력창, 완료된 요청, 다크 모드를 눌러 봤다. `index.html`의 CSS와 렌더 함수, `ui/decide.js`·`strip.js`·`tasks.js`·`shell.js`, `state.js`의 라벨 상수를 읽었다. 스크린샷은 `shots/`에 있다. 수치는 브라우저에서 잰 값이다.

## 가장 큰 다섯 가지

1. **폰에서 결정 카드가 화면 두 개 아래에 있다.** 사무실(1174px)이 먼저고 결정 패널은 y=1299에서 시작한다. 결정 탭을 눌러도 스크롤하지 않고, 탭에 개수 배지가 없다. 고정 UI가 세로의 24%(데모 안내가 있으면 35%)를 덮는다(항목 17·18·19).
2. **결정 카드의 위계가 거꾸로다.** 무엇을·얼마나·왜가 12~14px 회색이고 `reason`·`detail` 같은 영어 라벨이 그대로 나온다. 카드 한 장이 폰에서 336px, 승인 버튼은 56×40px에 흰 글자/초록 3.4:1이다(항목 20·10·26).
3. **색 하나가 여러 뜻을 맡는다.** 초록은 작업 중이면서 승인 버튼이고, 노랑은 결정 대기이면서 경고이고, 파랑은 HPC이면서 링크·포커스·제안 카드다. 같은 "내가 할 일"이 카드마다 다른 색이다(항목 9·11).
4. **사무실과 작업판의 구조가 결과를 가린다.** 구역당 3~4석이라 오른쪽 절반이 빈 바닥인데 콘텐츠는 986px라 안에서 스크롤한다. 완료된 요청은 내용이 든 4열이 화면 밖에 있고 보고서는 그 아래에 있다(항목 2·4).
5. **토큰이 없다.** 글자 크기 12종, padding 41종, 반경 10종, 터치 높이 7종이고 12px 이하 글자가 텍스트의 45%다. 시안마다 같은 문제가 재발한다(항목 7·11·12).

읽는 법: P0은 첫 시안부터 반영, P1은 시안을 고른 뒤 구현에 반영, P2는 다듬기다. 범위는 S(CSS·문구 수준), M(컴포넌트 하나나 화면 하나 재설계), L(셸·구조 변경)이다.

## 유지할 것

- 동물 캐릭터와 책상 구성은 랩의 정체성이다. 위계 문제는 캐릭터가 아니라 둘레 정보에 있다.
- 다크 모드, `:focus-visible`, `prefers-reduced-motion`, `aria-label`, 안전 영역(`env(safe-area-inset-*)`) 처리는 이미 갖췄다.
- 탭 구조(결정·작업판·메신저·HPC)의 이름 붙이기는 PI가 이미 익혔다. 4개를 5개로 늘려도 이름은 그대로 둔다.

## 참고 사이트의 느낌을 옮기는 방법

- nf-co.re: 흰 바탕에 선 하나로 구역을 나누고 상태는 작은 알약 배지로 둔다. 카드 안에 카드를 넣지 않는다.
- research.meta.ai: 한 화면에 큰 제목 하나, 넉넉한 여백, 설명은 한 단 작게 둔다. 결과 카드의 첫 줄에 쓰면 맞는다.
- neurology.org: 가는 구분선과 작은 대문자 라벨, 촘촘하지만 정돈된 목록이다. 메신저와 HPC 목록에 맞는다.
- 색은 베끼지 않는다. 중립 회색 + 강조색 하나 + 상태색 넷으로 시작한다.
