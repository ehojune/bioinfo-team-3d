# #1374 재현 재실행 (2차)

## 결론
`labhq verify <request_id> --rerun`이 끝난 요청의 로컬 단계 스크립트를 PI 확인 뒤 새 임시 폴더에서 다시 돌리고, 선언된 산출의 sha256을 단계가 끝날 때 기록한 값과 비교한다. 결과는 게시 영수증의 실행 상태가 된다. `cso.py`는 바꾸지 않았다.

## 바뀐 것
- `labhq/reproduction_receipt.py`: `rerun_plan`(실행 전 단계별 스크립트·명령·비교 산출), `rerun`(입력·스크립트만 복사한 임시 폴더에서 이름 순 실행, hash 비교, 원래 폴더 산출 변경 시 `wrote_outside`), `rerun_summary`, `rerun_path`. `receipt_summary`가 저장된 재실행을 `execution`으로 보인다.
- `labhq/result_storage.py`: 게시 때 `state/reproduction/<id>.json`을 영수증 `rerun`에 붙인다.
- `labhq/evidence/audit.py`: `rerun_steps`(찾은 작업 폴더·선언 산출·기록 hash·HPC 여부), `render_rerun_plan`, `render_verify`의 재실행 줄.
- `labhq/cli.py`: `--rerun`, `--yes`, `--rerun-timeout`. 실행 전 명령을 보여 주고 묻는다. `--json`은 `--yes`가 있어야 실행한다. 불일치·실패는 exit 1이다.
- manual 07·13 한영.

## 실행한 것
- 새 시험 8건(`tests/test_reproduction_receipt.py` 4, `tests/test_labhq_verify.py` 4): 계획, 재현 통과, hash 불일치·실패·임시 폴더 밖 쓰기, 영수증 반영, 거절 시 무실행, `--yes` 기록 저장, 불일치 exit 1, `--json`은 `--yes` 필요.
- verify·영수증·보고서 210건, 게시·bench 244건 통과(로컬).

## 미해결
- HPC 단계 재실행은 없다("재현 실행 안 함(HPC)"). HPC가 다시 켜지면 붙인다.
- OS 격리가 아니다. 네트워크와 임시 폴더 밖 경로 접근은 막지 않고, 원래 단계 폴더 산출 변경만 감지한다.
