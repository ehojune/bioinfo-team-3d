# #1308 후속 — 잡마다 새 원격 폴더

- 원인: #1311 리뷰가 "클러스터에서 결과 파일을 검사한 뒤 읽기 전에 같은 작업 폴더의 다른 잡이 링크로 바꾸는" 경쟁을 지적했습니다. 공유 `work` 폴더가 문제였습니다.
- 바뀐 것
  - `labhq/hpc_transfer.py`: `job_spec`이 `<task>/job-<무작위 12자>` 폴더를 정하고 스크립트·로그·`work`를 그 안에 둡니다. `Transfer.make_fresh_dir`는 `mkdir -m 700 --`(`-p` 없음)로 폴더를 만들어, 이미 있는 이름(링크 포함)이면 실패합니다. 만든 뒤 `pwd -P`가 작업 폴더 아래인지 확인합니다. `upload_job`은 먼저 이 폴더를 만들고 그 안에 `logs`·`work`를 만들어 올립니다. 새 폴더라 미리 깔린 것이 없고 이름을 알 수 없어 다른 잡이 건드릴 수 없습니다.
  - 제출 승인 화면의 스크립트도 이 폴더의 `work`로 `cd`합니다(승인 전에 이름이 정해집니다). 회수·재시도는 저장한 `spec`의 같은 폴더를 씁니다.
  - 로컬 입력은 이미 병합된 #1311에서 `HeldDir`로 열어 둔 핸들에서 `fstat`·read합니다(`O_NOFOLLOW` 상당; Windows는 핸들이 열려 있는 동안 폴더가 바뀌지 않게 잡음). 업로드 입력 제외도 병합됐습니다.
  - `mktemp -d` 대신 `mkdir`(`-p` 없음)와 클라이언트가 정한 무작위 이름을 썼습니다. 결과는 같고(새 폴더, 700, 이름 비공개), 승인 화면에 경로를 미리 보여 줄 수 있고 클러스터에 `mktemp`가 있다고 가정하지 않아도 됩니다.
  - manual 09·15 한·영.
- 시험: `tests/test_hpc_transfer_1308.py` 64건(10건 Windows에서 건너뜀). 잡마다 다른 폴더, 이미 있는 폴더 거부(심어 둔 파일은 그대로), 링크가 심어진 이름 거부(밖에 아무것도 안 생김), `mkdir -m 700` 형태(`-p` 없음) 확인, 기존 시험의 폴더 경로 갱신. WSL(Linux)에서 전송·세션 시험 94건 통과.
- 한계·미검증: 실제 셸·실제 ssh는 보지 않았습니다. 같은 사용자의 잡은 이론상 서로의 폴더를 열 수 있지만 이름을 모릅니다(권한 700은 같은 계정에는 막이 되지 않음).
