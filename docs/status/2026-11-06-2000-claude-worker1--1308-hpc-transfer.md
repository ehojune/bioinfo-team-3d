# #1308 — HPC 세션으로 파일 올리기·가져오기 (#1295 E)

- 바뀐 것
  - `labhq/hpc_transfer.py`(새): `Transfer`가 세션 셸(`run`)로 파일을 주고받습니다. 올리기는 base64 블록(2400자)을 임시 파일에 이어 쓰고 `sha256sum`이 로컬과 같을 때만 `mv`합니다(다르면 `HashMismatch`, 임시 파일 삭제). 가져오기는 `tail|head|base64` 블록으로 받아 sha256을 계산하고 전체 파일은 클러스터의 `sha256sum`과 대조합니다. 경로는 안전한 글자의 상대 경로만(`..`·절대·공백·따옴표·글롭·선행 `-` 거부)이고 모든 값은 `shlex.quote`로 명령에 들어갑니다. 클러스터에서 `pwd -P`로 실제 폴더를 구해 작업 폴더 밖으로 나가는 링크 폴더·링크 파일은 거부합니다. 로컬 쓰기는 `write_confined`(링크 통과·밖 쓰기 거부, 임시 파일 뒤 교체).
  - 상한: 올리기 파일당 512KiB, 가져오기 파일당 1MiB(로그는 끝부분 `tail`)·잡당 8MiB, 입력 20개·합계 4MiB. 넘는 파일은 막고 "사이트 프로필의 전송 방법(로그인으로 셈)"을 안내합니다.
  - `Scheduler.transfer()`: 프로필에 `remote_workdir`가 있을 때만 `Transfer`를 돌려줍니다(없으면 기존대로 같은 경로를 쓰는 공유 파일시스템).
  - `labhq/runner/hpc_jobs.py`: 전송 사이트에서 `build_script`의 `cd`를 클러스터 작업 폴더로 바꾼 스크립트를 PI에게 보여 주고, 승인 뒤 게이트 안에서 올리기(스크립트와 선택적 `inputs`)가 끝난 다음에만 제출합니다. 올리기가 실패하면 제출하지 않습니다.
  - `labhq/runner/daemon.py`: 잡이 끝나면 에이전트를 깨우기 전에 로그·작은 결과를 가져와 로컬 `jobs/logs/`와 `output_dir`에 쓰고 `jobs/logs/<스크립트>.fetch.json`에 sha256과 건너뛴 파일을 기록합니다. 실패는 다음 폴링에 다시 시도(3번)하고 알립니다.
  - manual 09·15 한·영, Windows 시험 목록.
- 시험: `tests/test_hpc_transfer_1308.py` 34건(가짜 gateway의 샌드박스 폴더가 클러스터 파일시스템). 올리기·큰 파일·블록 변조·크기 상한·경로 거부 14종·링크 탈출·링크 파일·가져오기 sha·로그 끝부분·목록·로컬 쓰기 가둠, 제출 전 올리기·실패 시 미제출·입력·`cd` 없는 스크립트, 끝난 잡 회수와 재시도. 관련 묶음 1902 passed. 링크 5건은 Windows에서 건너뛰고 WSL(Linux)에서 86건 통과를 확인했습니다.
- 한계·미검증: 실제 ssh·PTY·실제 셸은 보지 않았습니다. 원격 명령은 `mkdir`·`pwd -P`·`printf`·`base64`·`sha256sum`·`mv`·`test -L`·`wc`·`tail`·`head`·`tr`·`find -printf`(GNU)이고 가짜 gateway가 같은 형태를 흉내 냅니다. 큰 파일의 사이트 전송 자동 실행은 없습니다(안내만). 올리기는 한 줄 3000자 안쪽 블록이라 큰 파일은 느립니다. 로그인 카운터는 건드리지 않았습니다(같은 셸).
