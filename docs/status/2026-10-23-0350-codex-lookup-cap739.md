## #858 요청 전체 공개 조회 시도 상한 (source 9a10aef, base 5ea970f)

- 배경: 시운전 B(#739)의 고정 계약은 한 요청에 공개 문헌 조회 시도 9회다(실패·재시도 포함). 제품에는 단계별 20분 상한과 기관 경로 상한만 있었고 요청 단위 admission이 없었다(독립 검토 P2-5).
- 바꾼 것:
  - `annot.request_lookup_limit`(선택, 기본 없음) 설정을 더했다.
  - runner broker에 `/lookup/admit`·`/lookup/finish`를 더했다. 기록은 `runner/lookup_admission.py`가 `runner.state_dir/lookup_admission.sqlite3`에 남긴다.
  - `labhq_annot`의 모든 도구가 HTTP client를 만들기 전에 admission을 받는다.
  - 상한이 켜지면 runner가 작업 env에 `LABHQ_LOOKUP_ADMISSION=1`을 넣는다.
- 세는 단위: `labhq_annot` 도구 호출 한 번이 한 시도다. 실패·시간 초과·캐시 답·반복 호출도 센다. 한 호출 안의 HTTP 재시도·페이지 넘김·redirect는 따로 세지 않고, 그 행의 `outbound_requests`에 남긴다. 거부된 호출은 세지 않는다.
- 요청 구분과 원자성:
  - 요청 id는 broker가 작업 token에 묶은 값만 쓴다. 호출 body가 다른 요청을 적으면 403이다.
  - SQLite `BEGIN IMMEDIATE`로 세고 기록하므로 같은 요청의 직원·단계·재시작·동시 호출이 한 상한을 쓴다.
- fail closed: broker token·runner ledger·request id가 없거나 broker에 닿지 못하면 조회하지 않고 도구 오류로 돌려준다.
- 기본: 설정이 없으면 broker를 부르지 않는다. 기존 동작과 같다.
- 검사:
  - `tests/test_external_wait.py`에 test 5개(case 11개)를 더했다.
  - 로컬 in-process로 ledger·동시성·MCP 쪽 case가 통과했다. 파일 전체는 33 passed다.
  - broker·runner 연결 test 3개는 로컬 venv에 fastapi·websockets가 없어 CI 몫이다.
  - 3.10 AST, public, diff 검사를 통과했다.
- 남은 것:
  - 웹 검색·외부 HTTP MCP·셸 네트워크는 막지 않는다. 시운전 직원 구성에서 빼야 한다.
  - runner가 둘이면 따로 센다.
  - AlphaGenome SDK와 기관 browser 경로의 요청은 `outbound_requests`에 잡히지 않는다.
  - 실제 runner·시운전에서는 확인하지 않았다.
