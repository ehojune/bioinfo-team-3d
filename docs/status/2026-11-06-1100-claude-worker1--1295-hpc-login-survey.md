# #1295 — HPC 로그인 경로 조사 (읽기 전용)

- 결론: ssh를 여는 곳은 `Scheduler._run` 한 줄이고, 로그인의 거의 전부가 runner의 잡 감시(60 s마다 잡마다 `status`)에서 나옵니다. 4 h 잡 하나에 약 241건, 동시 잡 3개면 약 723건(코드로 계산한 추정, 실측 아님).
- 줄이는 순서(문서에 비교): 한 번에 묻기 → 조회 간격·backoff → 로그인 상한 → 가능한 사이트는 완료 표지 파일 읽기 → 그래도 필요하면 WSL ControlMaster(사람이 연 마스터에 올라타기). 장수 셸 세션과 라이브러리는 권하지 않습니다.
- 바뀐 것: `docs/reference/hpc-login-survey-1295.md`만 추가. 코드·설정 변경 없음.
- 미확인: 실제 HPC 접속·로그인 수 측정 없음. 전산팀이 로그인을 연결당·세션당 중 무엇으로 세는지 모름(ControlMaster 효과가 여기에 달림). Windows 기본 OpenSSH의 다중화 미지원은 공개 이슈로만 확인. WSL ControlMaster의 실제 동작과 완료 표지가 성립하는 사이트는 확인하지 못함.
- 다음: PI가 로그인 기록 방식과 하루 상한을 정하면 구현 순서를 정합니다. 구현은 별도 승인.
