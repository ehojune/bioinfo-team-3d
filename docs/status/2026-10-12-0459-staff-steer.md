## 2026-10-12 · 실행 중 직원 제어: 방향 바꾸기·일시 정지·멈추기 (#59 ①)

- 결론: PI가 실행 중인 직원에게 방향을 보내고, 일시 정지·재개하고, 세션을 남긴 채 멈출 수 있다. 쓰기 가능한 Claude 실행은 도구 hook으로 즉시, 다른 엔진은 turn 경계에서 같은 요청을 받는다. 멈춘 단계는 실패가 아니라 `halted`로 남아 PI 재개를 기다리고, 재개하면 같은 세션으로 이어 간다. 2절 폭주 차단기는 건드리지 않았다.
- 바뀐 것:
  - hook(`labhq/hooks/control.py`, 표준 라이브러리만): PreToolUse는 멈춤이면 `{"continue": false}`, 정지 중이면 최대 5분 붙잡은 뒤 "PI가 일시 정지함"으로 deny. PostToolUse·PostToolUseFailure는 멈춤이면 `continue: false`, 아니면 대기 중인 방향을 `additionalContext`로 한 번 전달하고 파일에서 지운다. 대기열 20개, 넘치면 오래된 것부터 버리고 버린 수를 함께 알린다. 한 번 전달은 9,000자 이하로 나눈다(Claude 상한 10,000자).
  - runner(`labhq/runner/control.py`): 제어 파일은 `runner.state_dir/control/<task>.json`(직원 쓰기 범위 밖). gateway `task.control`을 seq로 한 번만 적용하고 `control.ack`를 보낸다. hook이 없는 실행(Codex 등, 읽기 전용 Claude)은 남은 방향·정지를 session id에 붙여(`control_carry`) 다음 resume turn 앞에 방향을 붙이고, 정지면 그 turn을 재개까지 시작하지 않는다. 멈춤은 hook 실행이면 60초 유예 뒤, 아니면 바로 프로세스를 끝내고 session id를 남긴다.
  - gateway: `POST /api/tasks/{id}/steer|pause|resume|halt`(PI 토큰, 방향 2,000자). 취소처럼 보관했다가 runner 재연결 때 순서대로 다시 보내고 ack로 지운다. `agent.control` 상태를 snapshot의 `running_tasks[].control`에 싣는다. 멈춘 단계는 `waiting_pi`로 park하고, `/resume`이 park를 풀어 같은 세션으로 다음 turn을 보낸다(`failure_kind`는 `halted`를 terminal로, 재시도·환경 수정 없음).
  - CLI `labhq task steer|pause|resume|halt <id> [text]`. 웹 직원 상세 시트에 실행 중일 때만 방향 입력·일시 정지/재개·멈추기, 상태 `일시 정지됨`·`멈춤 · 재개 가능`. 작업판 단계 상태 `halted`.
  - `docs/manual.md` 직원 제어 절(엔진별 표).
  - 설계에서 더한 것: 정지는 바로 deny하지 않고 도구 호출을 최대 5분 붙잡는다(바로 거부하면 Claude가 turn을 끝내 단계가 미완성으로 끝남). 멈춤은 PostToolUse 외에 PreToolUse에서도 걸고, hook이 60초 안에 멈추지 못하면(긴 명령 중) runner가 끝낸다.
  - 리뷰 반영(15bbd6a, 봇 리뷰 P1 1건·P2 3건): runner는 제어 파일을 쓰지 못하면 두 번 더 해 보고(0.2초·1초 뒤), 그래도 안 되면 ACK 없이 직원 기록에 경고만 남긴다. gateway가 보관한 제어는 재연결 때 다시 와서 적용된다. ACK는 적용, 이미 적용한 seq, 이 runner에 대상이 없는 경우만 보낸다. 적용한 seq는 최대값이 아니라 집합으로 제어 파일과 끝난 task 기록(`control_ended`)에 남겨, 재전송은 carry가 다음 turn에 쓰인 뒤에도 한 번만 적용되고 늦게 다시 온 낮은 seq도 한 번은 적용된다. pause/resume은 마지막 것이 이긴다. 웹 reducer는 직원별 실행 중 task를 Map으로 추적하고 시트는 task마다 제어 줄을 그려 그 줄의 task id로 보낸다. 멈춘 단계의 재개 기한이 지나면 `request.step_halt_expired`를 내보내 재개 줄을 지우고 단계를 실패로 보인다.
  - 리뷰 2차(4f880ca, P1 1건·P2 4건). 불변식: 제어(방향·정지·멈춤과 carry)는 쓰일 때까지 `runner.state_dir`에 남는다. 방향은 hook이 전달하거나 그 방향을 담은 프롬프트로 CLI가 시작될 때(`on_started`), 정지는 풀릴 때, 멈춤은 `halted` 결과가 나올 때 쓰인 것으로 본다. carry는 task 시작 때 가져가지 않고 쓰인 만큼만 줄인다. task 파일에 agent·session(엔진이 알려 주면 `on_session`)을 적어 두고, runner를 다시 띄우면 남은 파일을 carry로 되돌리며, 멈춤을 받은 task의 interrupted 결과는 `halted`다. carry 키는 (agent, session)이고 늦게 온 제어 기록도 같은 주인을 쓴다. 실행 순서를 기다리는 turn은 semaphore와 멈춤을 함께 기다려 멈추면 CLI 없이 `halted`로 끝내고, hook 없는 엔진의 수신 문구는 멈췄다고 말하지 않는다. 멈춘 단계의 대기가 요청 취소로 끝나도 `request.step_halt_expired`(reason `cancelled`)를 낸다. HPC·답 대기로 들어간 task는 정지 상태를 snapshot에 남긴다.
  - 기존 test 3곳: `test_observed_outputs`는 PostToolUse 항목을 명령으로 골라 보고, `test_ask_review3`는 `run_task` 본문이 `_run_task`로 옮겨 간 호출 위치를 센다. `test_web_3d` 목록에 새 node test를 넣었다.
- 실행한 것: hook 계약은 공식 문서로 확인했다(https://code.claude.com/docs/en/hooks 의 PreToolUse·PostToolUse decision control, JSON output `continue`/`stopReason`, matcher, timeout 600초; 재개는 https://code.claude.com/docs/en/headless). 실제 `claude -p`는 부르지 않았다. 새 test 28개(`tests/test_staff_control.py`, 리뷰 반영은 `tests/test_staff_control_review.py` 4개와 `tests/test_staff_control_round2.py` 6개(runner 재시작 포함): 문서 예시 payload로 hook 명령 subprocess, 1회 전달, 큐 상한, deny, halt, runner 파일·carry·정지 hold, hookless kill, API 인증·전달·재전송, halt park→재개)와 `tests/web_staff_control.cjs`·`tests/web_staff_control_tasks.cjs`. 리뷰 반영 test 4개와 node test 1개는 c0364a3에서, 2차 test 6개는 03f5277에서 실패하는 것을 따로 확인했다. Windows 전체 `pytest -q` 5356 passed·66 skipped(리뷰 2차 뒤), `for f in tests/*.cjs; do node --test "$f"; done` 34개 통과, `scripts/check_public.sh`, `scripts/patch_notes.py check` 통과.
- 미해결: (1) 실제 Claude에서 `continue: false` 뒤 같은 session id로 resume하는 실측은 하지 않았다(문서 근거만). (2) hook은 도구 호출마다 Python을 두 번(Pre·Post) 띄운다. 이 PC에서 한 번에 약 0.2초. (3) 정지 중 붙잡힌 도구 호출은 무응답 경고를 낼 수 있다. (4) gateway 재시작 때 멈춘 단계의 park는 다른 PI 대기처럼 사라지고 요청은 `중단됨`이 된다. 엔진이 session id를 알리기 전에 runner가 꺼진 새 세션 task의 제어는 이어 받을 세션이 없어 파일로만 남다가 2일 뒤 지워진다. (5) Gemini·Antigravity처럼 세션을 이어 쓰지 못하는 엔진은 방향과 다음 turn 정지가 닿지 않는다.
