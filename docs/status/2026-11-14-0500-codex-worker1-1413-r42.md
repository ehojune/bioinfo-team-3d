# #1413 — HPC 요청 입력과 고정 노드

## 결론

기존 요청 입력은 선택 runner에서 사전 검사하고 PI가 승인한 hash의 snapshot으로 전달한다. Slurm 고정 후보는 한 노드만 요청한다.

## 바뀐 것

- briefing 전 무모델 preflight, 승인 결합, 재개 시 새 검사와 전송·제출 전 무결성 검사를 추가했다. 구형 runner와 검증 실패는 거부한다.
- Slurm의 충돌 배치 옵션, 다른 cluster 환경변수와 고정 노드의 `submit_prefix`를 거부한다. 자원이 부족해도 후보나 노드 수를 늘려 재제출하지 않는다.
- 한영 manual과 Windows test 목록을 갱신했다.

## 실행한 것

- 관련 Windows fixture 회귀 536 passed, 47 skipped. POSIX helper 단독 fixture에서 정상 입력 수용과 변조·누락·빈 폴더 추가 거부를 확인했다.
- 원격 shell 전송은 파일당 512 KiB 한도다. Linux CI의 전송 통합 시험과 최종 head CI·실제 리뷰는 PR에서 확인한다.

## 미해결

- 실제 scheduler 동작, 두 노드 배정의 원인과 PI 인스턴스 배포는 검증하지 않았다.
