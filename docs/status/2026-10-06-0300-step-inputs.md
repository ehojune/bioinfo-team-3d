## 2026-10-06 · #423 — 앞 단계 입력을 inputs/로 잇고 보고하지 않은 산출도 묶음에

- 결론: 벤치 C t6의 재현성 결함 둘을 고친다(PI 10-06: inputs/ 방식, Claude 구현). 직원 스크립트가 앞 단계 파일을 runner 절대경로로 나눠 적어 묶음에서 안 돌았고, 스크립트가 읽던 미보고 파일(gene-set 사본·그림 등)이 묶음에 없었다.
- 바뀐 것: runner가 실행 전에 단계 폴더 `inputs/<앞 단계 id>`를 앞 단계 `outputs/`에 링크한다(POSIX symlink, Windows junction; 남은 링크는 새로 걸고 진짜 폴더는 건드리지 않음). CSO가 주는 앞 단계 파일 목록은 `inputs/<id>/...` 상대경로이고, 단계 프롬프트는 스크립트에 절대경로를 쓰지 말라고 한다. 링크를 못 걸면 이유와 원래 경로를 프롬프트에 적는다. HPC 제출 검사는 `inputs/` 바로 아래 링크만 지나친다(따라가거나 chmod하지 않음). 요청 묶음은 기록된 산출을 다 복사한 뒤 남은 상한 안에서 보고하지 않은 산출을 `copied (unreported)`로 복사하고(빠져도 incomplete 아님), 의존이 있으면 `link_inputs.py`와 README 첫 명령을 넣는다.
- 실행한 것: 새 test 4건(링크로 읽기·낡은 링크 교체·진짜 폴더 보존, 열리지 않은 앞 단계 안내, 미보고 산출 순서·상한, 묶음을 옮긴 뒤 `link_inputs.py`로 스크립트 재실행). 프롬프트 고정 hash 3곳 갱신. 전체 pytest 3947 passed·54 skipped, `scripts/check_public.sh`.
